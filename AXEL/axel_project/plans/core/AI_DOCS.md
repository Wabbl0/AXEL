## Combat invariants

Unless explicitly redesigning:

- 5×5 grid; deterministic RNG; line wins 3+ rows/cols (no flood-fill cluster wins).
- Wild: only exactly-3 winning lines spawn wild in the middle cell. The wild picture has no grey halo.
- Multiplier tied to cascade progression.
- Paytable values in `combat/data/symbols/sym_*.tres` are whole numbers (no decimals): low symbols pay 2 / 4 / 15, red heart 3 / 5 / 20, cigarette, alcohol and bloody hand 5 / 12 / 50, satanic 15 / 25 / 280 for 3 / 4 / 5 in a line. `CombatRoot.PAYTABLE_SCALE` (10) divides them back inside `_line_payout_cents`, so one line pays the same chips as the old decimal table (bet x value x multiplier x 0.431 / 10). Bets, balance and the goal ladder did not change. The history box shows `bet x value x multiplier`.
- A cleared grid pays nothing extra. The line wins that emptied it already paid. A Vice Round clear still starts Free Spins.
- Power map: powers are named after their symbols — `cigarette`, `alcohol`, `bloody hand` (code ids are `cigarette` / `alcohol` / `bloody_hand`). Prefer the name “alcohol” (not “booze”) in docs and user-facing text. When one of those powers changes cells, the cells play a 0.48s white-to-grey motion (bloody hand morphs, alcohol is eaten by the wild skull, cigarette burns to ash) instead of the old 0.25s pause. The power-icon hold is 0.31s so the whole activation stays 1.75s. Do not add another wait on top. Headless and sync spins skip the motion. Regression: `combat/test/power_act_fx_check.gd`.

## Design ideology

From a senior developer's playtest feedback (2026-10). Treat as guiding intent for all balance and onboarding work.

- Like most roguelikes, AXEL lives on the fine line between difficult and replayable.
- The difficulty curve is almost exponential: the first third of the game is quite linear and easy. The difficulty spikes only after every technique has been properly explained and understood by the player.
- A win the player cannot explain feels empty. The senior developer did not know Moon Princess-style slots, did not understand what was going on, and felt nothing when he won the first round. Every first-time mechanic (matching, points, history box, skull meter, Vice Round) must be explained at the moment it happens.
- Tutorial cards close when the player does the action they ask for, or on their red X. They do not close on a reading timer.
- Walk fights stay almost impossible in the first areas and only become common in the late areas.

## How to work

- Plans = design truth; code = behavior truth — reconcile before changing mechanics.
- Always-on Cursor rule (`.cursor/rules/axel-ai-docs-governance.mdc`) is a pointer only — **read this file first**, then the matching plan (`SCENE_BUILDING.md` for rooms/player, combat plans when the prompt is combat, `AI_CHANGELOG.md` only for recent history). Do not treat the `.mdc` as the rulebook.
- Ask before large or ambiguous scope; do not assume unstated layout, economy, or behavior.
- Prefer scoped, additive edits; keep combat deterministic and replayable.
- No machine-absolute paths in shared gameplay code.
- Never add comments of any kind (`#` or `##`) in any project source, including GDScript docs comments. Plans/markdown headings may still use `##`. Do not mass-delete existing comments unless asked.
- If a prompt breaks established rules, remind the user of those rules before implementing. Most often the new prompt becomes the new canon after that reminder/confirmation.
- If a prompt wants a hardcoded player spawn, a first-layout skip, or spawn derived from another node, remind: **Player node is the spawn**.
- If tuning a **door arrival**: re-read the dest scene’s live InteractArea / ExitTrigger in **this** session (`InteractArrival` after cover-fit). Do not reuse spawn numbers from an earlier turn. Do not “fix” the live box with `BOTTOM` + `resolve_inside_clearance` unless the user asked. Hard spawns stay listed in `SCENE_BUILDING.md`.
