## Combat invariants

Unless explicitly redesigning:

- 5×5 grid; deterministic RNG; line wins 3+ rows/cols (no flood-fill cluster wins).
- Wild: only exactly-3 winning lines spawn wild in the middle cell. The wild picture has no grey halo.
- Multiplier tied to cascade progression.
- Power map: powers are named after their symbols — `cigarette`, `alcohol`, `bloody hand` (code ids are `cigarette` / `alcohol` / `bloody_hand`). Prefer the name “alcohol” (not “booze”) in docs and user-facing text.
- Bonus sequence (unambiguous): **normal spins → Vice Round → Free Spins**. Vice Round ≠ Free Spins. Never call Vice Round “Free Spins.” Replace “SUPER Free Spins” with **Free Spins** everywhere. Free Spins starts if Vice Round clears all non-wild symbols (no new symbols spawn during Vice Round). During Vice Round each vice power activates once in order: bloody hand (then matches), then alcohol, then cigarette.
- Item ids: extended `TIER-FAMILY` uppercase (`C-A`); baseline digit suffix (`C1`). New mechanic default = five tiers total (Common → Uncommon → Rare → Epic → Legendary) unless one tier or a subset is requested. Player-facing item names use Vice (not Trinity). File stems / `effect_id` may still say `trinity`.
- Fights end when the player cannot afford another paid spin, or when GOAL is met. There is no playtest Limit spins / Budget / Used control. F6 and live fights both use `combat/combat_test.tscn` (`combat_run` is gone). A live fight shows equipped items; the locker tutorial shows the empty DVD.
- Catalog edits only in `plans/combat/AXEL_COMBAT_ITEM_CATALOG_PLAN.md`.
- **Protected scaffold:** `combat/combat_test.tscn` — keep `%CombatRoot`, `%MetaBox`, `%SeedSpinBox`, `%SpinButton`, `%BankrollLabel`, stake row, Free Spins choice buttons. Run `combat/test/combat_test_scaffold_check.gd` before combat edits.
- **Debug combat tools:** Autoload `AxelCombatDevTools` (`scripts/debug/axel_combat_dev_tools.gd`) — editor/debug-only (`OS.is_debug_build()`); inactive in release. Must not change release RNG or determinism. Pause opens the same panel in rooms and fights. A session switch on that panel blocks world fight starts (walk, pickups, memories, locker tutorial) without hiding floor items. The switch is not saved and starts off.

## How to work

- Plans = design truth; code = behavior truth — reconcile before changing mechanics.
- Always-on Cursor rule (`.cursor/rules/axel-ai-docs-governance.mdc`) is a pointer only — **read this file first**, then the matching plan (`SCENE_BUILDING.md` for rooms/player, combat plans when the prompt is combat, `AI_CHANGELOG.md` only for recent history). Do not treat the `.mdc` as the rulebook.
- Ask before large or ambiguous scope; do not assume unstated layout, economy, or behavior.
- Prefer scoped, additive edits; keep combat deterministic and replayable.
- No machine-absolute paths in shared gameplay code.
- Do not add `##` comments in any project source (GDScript docs comments included). Use `#` only if a comment is needed. Plans/markdown headings may still use `##`. Do not mass-delete old `##` lines unless asked.
- If a prompt breaks established rules, remind the user of those rules before implementing. Most often the new prompt becomes the new canon after that reminder/confirmation.
- If a prompt wants a hardcoded player spawn, a first-layout skip, or spawn derived from another node, remind: **Player node is the spawn**.
- If tuning a **door arrival**: re-read the dest scene’s live InteractArea / ExitTrigger in **this** session (`InteractArrival` after cover-fit). Do not reuse spawn numbers from an earlier turn. Do not “fix” the live box with `BOTTOM` + `resolve_inside_clearance` unless the user asked. Hard spawns stay listed in `SCENE_BUILDING.md`.
